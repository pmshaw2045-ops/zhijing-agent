## 各项详情

### 1. 集成测试

**现状**：130 项测试全部 mock LLM，没有一次真实 API 调用。

**收益**：信任度大幅提升。别人 fork 后能确认"真的能跑"。

**风险**：
- CI 跑集成测试需要真实 API Key → 必须可跳过（否则 PR 全红）
- 每次跑花真实 token 费用（~¥0.01/次）
- 可能因 API 网络波动假失败

**实现**：[待实施] pytest marker `@pytest.mark.integration`，CI 默认跳过，本地手动加 `--run-integration` 跑。

### 2. 前端 Build Tool

**现状**：`server.py` 手写 6 个 `@app.get("/xxx.js")` 端点。

**收益**：移除"业余"印象，但功能上无变化。

**风险**（🟠 不建议现在做）：
- 前端刚完成模块化拆分（1204→100 行），修复了 2 轮加载顺序/行号 bug
- 引入构建工具 = 推倒刚稳定的状态
- 6 个静态端点全部要改路径
- 当前无 npm 依赖需要构建，esbuild/Vite 是额外复杂度

**条件**：等到需要加 npm 包时再引入。

### 3. startup_diag 打印 232 行

**现状**：每次启动打印 232 行诊断输出，含 `find backend -name __pycache__ -exec rm -rf {} +` 建议。

**影响**：开源社区看到这条会觉得"项目有 bug 没修干净"。

**处理**：✅ 已完成。dev 模式保留（对开发者有用），prod 模式静默。不删 `startup_diag.py`。
