# 织镜 ZHÌJÌNG — 产品化路线图

> 2026-06-06 | 从 Demo 到产品的 10 项提升

---

## 阶段一：可交付（2-4周）

### 1. 流式报告渲染
**现状**：SSE 发完完整 JSON，前端等全部接收后一次渲染。用户等 60s 看白屏。

**方案**：LLM 输出改为 stream 模式，每 200 字发一个 `content_chunk` 事件，前端逐段追加。报告 JSON 格式不适合流式——改为先输出 paragraphs 文本流，再输出结构化 JSON 给前端渲染组件。

**价值**：从"60s 白屏"变"3s 开始看内容"。**感知速度提升 10 倍。**

### 2. 报告缓存 + 幂等
**现状**：相同 query 每次完整跑 Pipeline。竞品对标跑了 50 次太平鸟 vs 伊芙丽，花了 50 次 LLM 费用。

**方案**：`query + intent + params` 哈希 → 缓存池。24h 内命中直接返回。缓存过期后异步刷新。

**价值**：重复查询成本降 80%。用户"点错重试"零等待。

### 3. 错误恢复 + 优雅降级
**现状**：一个搜索工具超时 → 整个 Pipeline 挂。

**方案**：工具执行 3 次重试，超时后跳过该工具继续。报告末尾标注"部分数据源不可用"。

**价值**：可用性从 95% → 99.5%。

## 阶段二：可运营（4-8周）

### 4. 用量看板
**现状**：`/api/metrics` 返回 JSON，没人看。

**方案**：管理后台 `/admin`，展示：今日调用量、Token 消耗、费用、Top 用户、错误率趋势。数据存 SQLite → 存时序库。

**价值**：知道谁在用、花了多少钱、哪里出问题。

### 5. 多租户 + 限额
**现状**：一个 API Key 管所有人。

**方案**：用户注册 → 分配 `tenant_id` + API Key + 配额（日 50 次）。`AuthMiddleware` 验证租户+限额。超额返回 429 + 升级提示。

**价值**：可以从"团队自用"变"对外开放注册"。

### 6. 报告模板市场
**现状**：6 种报告固定在后端策略路由里。

**方案**：用户可创建"自定义报告模板"——选组件、调顺序、加品牌 Logo。模板存 JSON → `report.py` 动态渲染。

**价值**：从"工具"变"平台"，用户粘性提升。

## 阶段三：可商业化（8-16周）

### 7. 计费 + 支付
**现状**：无计费。

**方案**：按 Token 消耗计费（¥0.005/次选品分析, ¥0.01/次竞品对标）。预充值模式。接入 Stripe/微信支付。

**价值**：可以收费了。

### 8. 知识库 + RAG
**现状**：每次搜索实时调 API。

**方案**：用户上传品牌资料/竞品数据 → embed → 存入向量库 → 搜索时混合检索。减少对外部搜索依赖，提高准确度。

**价值**：从"通用搜索"变"企业知识库驱动"。

### 9. 协作 + 分享
**现状**：单人使用，报告无分享。

**方案**：生成分享链接（加密、可设有效期）。团队成员查看/评论。报告可导出 PDF/PPTX。

**价值**：从个人工具变成团队工具。

### 10. API + SDK
**现状**：只有 `/api/chat` 一个端点。

**方案**：开放 API 文档（OpenAPI/Swagger）。Python SDK：`zhijing.selection("连衣裙趋势")` → 报告对象。按调用量计费。

**价值**：可以嵌入客户自己的系统。**这才是 SaaS 的真正形态。**

| **高成本** | 多租户、计费、SDK | 模板市场、协作 |
